# Accelerated voice troubleshooting

This annex accompanies the [accelerated voice runbook](ACCELERATED_VOICE_TESTS.md). Preserve failed observations before applying a workaround; passing a later test does not erase an earlier failure.

## Known setup roadblocks

- A cached `OpenbaseFieldTest.app` may be unsigned. Rebuild for the physical-device destination with `-allowProvisioningUpdates`, then install through Appium. A cached APK can contain older behavior even when its real netmesh library is present; rebuild before claiming current-source coverage.
- Regenerate Tuist after `ios/Project.swift` changes. `OpenbaseFieldTest` is a physical field-test build scheme without a test action; use the `Openbase` scheme and a dedicated simulator for mocked unit tests. The UIKit auth package is iOS-only; a plain host `swift test` is not its supported test path. Test through an iOS Xcode destination.
- SwiftUI can report `visible=true` for an off-screen control, and `scroll_to_element` can stop before the control's center enters the viewport. Verify its bounds and screenshot. A row-wide Settings switch element can cover the text as well as the actual switch; tapping its center may do nothing. Tap the observed switch control and assert its new value. Recheck Verbose Audio Playback Diagnostics and the speaker route after installing a new build.
- Gradle needs a JDK even if an old APK exists. Set `JAVA_HOME` to an installed JDK 17 before rebuilding; do not infer a runtime from the presence of Gradle caches.
- Appium MCP's Android file-pull wrapper may send `path` where UiAutomator2 requires `remotePath`. If the registered tool reports that exact mismatch, use the field-test Settings action **Copy Voice Timing Diagnostics**, then retrieve the clipboard through Appium MCP. It flushes pending journal writes and exports up to 400,000 bytes of complete recent records. Check that the export covers the whole scenario; the fallback is bounded and cannot prove missing older intervals. Do not use an ad-hoc adb/WebDriver workaround.
- On some guest builds, `dnctl list` omits later pipes once a preceding pipe has active flow queues. Record both configurations before loading shaping rules and measure both traffic directions; a post-traffic textual omission alone does not establish that a pipe vanished. Treat an unmeasured direction as missing coverage.
- A local cached Electron bundle without a bundled runtime is not a signed-DMG installer sample. For developer voice tests use `./scripts/setup`; omit Electron or use the developer dashboard launcher from the developer runbook. Do not report the cache's missing CLI as an installation regression.
- Browser OAuth can open outside the existing Safari automation session. Adopt the real guest browser through the Tart Safari harness after confirming the Cloud origin, then use semantic controls. Disposable-guest helper approvals and credentials are agent-controlled; do not ask the user to operate the VM.
- Restart the guest voice worker with `openbase-coder services stop livekit-agent`, then `openbase-coder services start livekit-agent`. `services restart` is not a supported subcommand. Reconnect the physical call after replacing worker code; an existing room job continues to run its already-loaded module.
- Android's active VoIP call uses the voice-call stream; media volume and the app's volume slider do not establish its actual loudness. Check native `voice_call_volume` against `voice_call_max_volume` during a connected call, use physical-device volume keys through Appium MCP when needed, and verify the response acoustically. Speaker styling and decoded PCM alone do not prove audible room output. Record the SDK-selected route and native communication device rather than relying on deprecated speakerphone flags.
- Run Tuist generation before starting Xcode builds. Regenerating the project while a signed build is running can change entitlements and invalidate that build. Record the build result and actual Appium installation separately from the source commit.
- Read-only guest log and provenance observations retry at most three SSH transport failures. Do not retry a mutation whose acknowledgement was lost: inspect actual state first. Network restoration timers carry an ownership lease, so an obsolete timer cannot flush a newer profile's pipes or anchor.

Run all throughput probes to completion before acoustic recording. An overlapping upload competes with streaming STT inside the shaped guest; treat it as an explicit competing-traffic scenario rather than ordinary steady-state network coverage. Record network restoration in host events when it occurs during a capture. A VAD-only hold without any transcript must expire, while a hold owned by actual backend work or pending speech remains protected.

An AssemblyAI no-messages or no-audio warning can occur normally during silence or automatic muting. The collector labels it `stt_provider_warning`; the warning alone does not establish STT starvation. Establish a stall from an actual recorded input, transport state, missing transcripts, and the resulting recovery behavior. Historical `stt_provider_stall` labels require the same corroboration.

Inspect the visible Tart window promptly when a dispatched turn stops progressing. Precreating Desktop folders over SSH does not prove that the coding backend has Desktop permission: a different runtime can still trigger a modal. Record the actual Allow action as `vm_desktop_permission_allowed`, preserve the delayed run as partial evidence, and repeat from a fixture with the declared permission state. Do not count omitted, gated stimuli as successful steering. Core Audio capture metadata records the actual input device ID, name, and UID; record output routing separately and verify sound in the room recording.

Run `python3 voice-tests/measure_network.py <run-vm> <ignored-network-directory>` after applying a profile and before acoustic recording. It performs bounded, sequential Cloudflare HTTP download/upload probes with a generated zero-filled upload body and retains rates, durations, byte counts, and failure status. A failed direction remains unmeasured. Wait for the command to finish before starting the scenario; preserve its host start/end times beside the capture to prove that measurement traffic did not overlap input.

Specify the exact result path in each briefing, for example `~/Desktop/Maple/result.md`, separately from the React app directory. Agents can legitimately create a nested app folder; a missing result at a guessed parent location does not imply an active turn. Check actual thread status, locate the requested output, and run the build. Retain both canonical skill revision and guest runtime revisions when refreshing a fixture: dispatcher procedure changes are part of the tested source.

If a terminal word is ambiguous in the primary transcript, run `python3 voice-tests/secondary_transcript.py <run> --start-s <bounded-interval-start> --seconds 10 --credentials-file <private-env-file>` for an independent Deepgram Nova reading. It extracts only the Deepgram key, retains the original room WAV digest and clip offset, and preserves the primary transcript. Two providers agreeing still does not establish exact acoustic timing or the intended words: compare the actual backend text and waveform, and retain uncertainty instead of changing a failed marker into a pass.

After booting a fresh clone, service PIDs can appear before the API and LiveKit sockets are listening. Require a fresh `openbase-coder doctor` with all checks passing before the call; preserve earlier startup observations and recheck readiness rather than treating a PID as socket health or a transient boot warning as a product failure. Timing diagrams include registered VM STT excerpts and a full receipt-time table so input recognition errors can be distinguished from output clipping.

`finish.py` requires `--vm <run-vm>` and checks the dedicated fixture backend store for running, waiting, queued, or starting turns, including background agents. A premature native unmute does not authorize teardown while actual backend work remains pending. Capture the fresh phone snapshot immediately before running the helper; its freshness is checked after the backend observation. Do not end a call just because a recording deadline elapsed, or because one dispatcher delivery finished while agent announcements are still owed.

AVAudioEngine can report an internal `CADefaultDeviceAggregate` as its logical input. Capture metadata also records the system default input and output devices at recorder startup; retain both, and do not describe the internal aggregate name as proof of a particular physical microphone. These device observations are configuration evidence, while audible phone responses in the room recording establish the acoustic loop.

An app-control receipt timeout is an unknown outcome, not proof that the foreground app is closed or that the action failed. The phone may already have executed the command; inspect actual state before retrying. The diagnostics collector continues waiting for an observed log append after an unconfirmed receipt and records that distinction in `collection-attempts.jsonl`. Successful append observations clear the current upload error while preserving the prior error in history. Native Appium journals remain the authoritative fallback.

For extreme upload profiles, use `measure_network.py --upload-bytes 100000` (the default is one million bytes) so a bounded probe can finish within its 45-second limit. Retain the requested byte count and measured duration; small transfers include proportionally more connection overhead. A bounded secondary transcript is drawn in green alongside the unchanged primary ASR words in blue. An ASR word extending across a mute feedback sound is timing uncertainty until independently checked against the waveform and native mic application.

A stimulus may contain `segments: [{"text": "First instruction.", "gap_after_s": 1.8}, {"text": "Actually, use this correction."}]`; its top-level `text` must exactly equal those fragment texts joined with spaces. The capture harness synthesizes each fragment, converts to mono PCM, inserts sample-exact silence, and retains source digests and offsets. These offsets describe the fixture WAV, not exact speaker onset; use the recorded room waveform to verify acoustic pauses. Reused fixtures retain the same original WAV digest.

The reusable [fragmented-steer scenario](../voice-tests/scenarios/fragmented-steer.json) resumes with a correction after 900 ms of sample-exact silence. Compare actual input word timing with native mute acknowledgments and backend submission, then verify the corrected answer and its complete spoken ending. Do not call this active-turn steering unless the target's stored turn start/end timestamps show that the correction was accepted while that turn was running. An observation that the target was running before a long spoken input is insufficient: it can finish before dispatcher submission. The larger Tetris and chess briefings include behavioral validation to exercise meaningful background work.

The [Elm controlled-stall briefing](../voice-tests/fixtures/elm/briefing.md) is a separate targeted fault injection. Its foreground waiting command records a PID and start time, then waits for 180 seconds. Start a real Elm Super Agent and hear its unsolicited introduction; obtain a fresh native Listening permit while the command is still alive, then explicitly ask the dispatcher to stop that command and perform the corrected file task. On Claude-compatible threads the canonical dispatcher procedure uses `super_agents_steer` with `interruptCurrentWork: true` for that request. Normal steering retains its existing behavior. Record the SDK interrupt acknowledgment and correction submission, verify that the original wait did not naturally finish, confirm the process stopped and inspect the corrected file and spoken ending. A submitted steer that remains behind a running tool is pending, not an applied correction. Error or missing terminal results and a corrective response that never begins must not be reported as successful completion.

The [combined parallel-and-stall scenario](../voice-tests/scenarios/parallel-stall.json) reserves fifteen minutes for both app tasks, heading corrections, final verification and the later Elm injection. Stage Elm's briefing and hash it as an additional prepared asset when using this scenario. Its earliest offsets remain requests, not actual input times: the native Listening gates determine actual playback. Prepare all six WAVs before joining the call. The HTML diagrams retain all markers, abbreviated repetitive labels, searchable event metadata and downloadable event JSON/CSV; mic transition bars show native clock uncertainty separately from the approximate word-alignment allowance.

Reserve enough recording time for deferred background results. If a fixed recording ends with pending work, preserve its incomplete coverage and continue observing; retain any gap between recordings. Do not end the call, silently classify missing late speech as TTS truncation, or overwrite the original window's assessment. Native journals can preserve timing through a recording gap, but they cannot supply missing room-acoustic evidence.

After replacing a signed iPhone build, wait for onboarding to settle, reconnect Openbase VPN through its visible Connect control if needed, and verify the native call screen before starting capture. An element query immediately after activation can run before that screen appears. Keep the phone foreground during VM restart/clone socket tests; background/foreground would repair the connection and invalidate a claim that periodic heartbeats recovered it. Socket diagnostics retain native heartbeat sent/completed/timeout timestamps without logging credentials.

Use `capture.py --prepare-only` to synthesize a scenario into an ignored fixture directory before joining a call. It creates the scenario, WAVs and provenance without playing or recording. Pass that directory with `--reuse-stimuli` for real captures; reuse checks retained WAV digests and keeps fragment/pause metadata. This separates provider preparation from the acoustic observation window.

Deterministic Super Agent names are case-sensitive: `Orange` and `orange` map to different speaking names. Voice STT may lower-case a requested durable thread name. Use lower-case durable names in voice fixtures, verify the actual stored `name` and `agent_name` before naming targets in later stimuli, and compute completion commands from that exact stored name. Prefer folder/task targets in reusable steering audio; a conflicting person name and folder is an ambiguity scenario, not ordinary steering coverage.

Hash staged briefings with `provenance.py --asset Desktop/orange/briefing.md --asset Desktop/willow/briefing.md`; retain their portable paths and SHA-256 values as `test_assets` in the reviewed sealing provenance. After booting the fresh clone, run `provenance.py --fixture-manifest <manifest>` before any call. Missing or changed assets write evidence and fail validation. Source heads alone do not prove that staged task files survived cloning. Before sealing, flush guest writes and shut the guest OS down normally; do not assume the VM-process termination timeout proves macOS completed its own shutdown. Tart's [stop implementation](https://github.com/cirruslabs/tart/blob/main/Sources/tart/Commands/Stop.swift) sends SIGINT, while its [run implementation](https://github.com/cirruslabs/tart/blob/main/Sources/tart/Commands/Run.swift) handles guest stop requests separately. The post-clone asset hashes remain the actual evidence.

Prefer spoken “read the briefing file in each folder” to dictating an extension. “Dot markdown” can resolve to `.markdown`, whereas a staged file may be `.md`. Keep exact file names in the briefing and verify the agent used that actual file. A missing staged briefing or filename ambiguity is a harness finding even if the agent creates an otherwise valid app.

A completed agent turn or a generated result report does not prove that an app builds. Require each briefing to save the actual production build command, output and exit code after its latest changes, then independently run that command before accepting a spoken success claim. Record missing validation separately from a failed build. If the dispatcher claims a pass without that evidence, preserve the exact spoken claim and repair the reporting behavior as well as the app.

Ordinary dependency fetching or compilation can take longer than the permission-warning threshold. A protected Desktop path inside `cd ... && npx ...` or a package build command is not by itself evidence of a blocked consent dialog. Preserve actual tool start/result timestamps and inspect the guest UI before treating such a warning as a setup roadblock.

For a foreground socket stall with both calls idle, record the VM API process pause and its independently armed automatic resume. Native heartbeat events must show sent, timeout, and successful completion; confirm a fresh app-control command afterward without backgrounding the phone. `uv run --with matplotlib python voice-tests/transport_plot.py <capture> --paused-at <VM-UTC> --resumed-at <VM-UTC>` renders that evidence using the existing clock bounds. Set `--vm-resolution-ms` to the actual timestamp precision. This isolated recovery chart makes no mute/playback assertion.

## Provider failure and constrained-link interpretation

Preserve provider-error timing alongside lifecycle events. A missing ending can be a confirmed partial synthesis: record the provider's emitted audio duration, timeout, and stream failure separately from a later STT reconnect failure or agent departure. A backend text result is not proof that its complete audio played. The default provider receive timeout now permits a bounded 60-second gap; explicit caller connection options remain authoritative. A failed synthesis releases its hold after any partial audio playout and the phone's decoded quiet tail, while remaining a failed delivery in the ledger. Validate this recovery acoustically rather than relabeling it as full speech success.

The Web Backend row probes an external HTTP endpoint. A failed probe proves it unavailable from the guest, not that its remote process stopped. Keep that warning distinct from local process or listener failures, especially during traffic shaping. Service polling and STT/TTS traffic share the shaped link; describe effective HTTP measurements as observed throughput with connection overhead, never as verified wire capacity or packet loss.

Build tools may be installed outside the macOS Java registration list. If the Java discovery helper fails, locate an existing JDK 17 and set a task-local JAVA_HOME for Gradle; do not reinstall tools or alter the user's default runtime without first checking the developer setup. Run analysis with its declared dependencies, for example uv run --with scipy --with matplotlib python voice-tests/acoustic_alignment.py <run>. Prepare these dependencies before a steady-state acoustic recording. The capture output must be a new directory; keep pre-call clock evidence in a separate staging directory and copy it into the new output after capture starts.

The acoustic harness holds an exclusive workspace lease during recording and fixture preparation, including batch transcription and clock collection. It rejects a second capture or prepare-only run until the first exits, so future-stimulus provider downloads cannot silently compete with a steady-state observation. Help remains available during a capture. Prepare every planned stimulus before starting an acoustic session.

LiveKit quick reconnect can leave the SDK connection state at connected. The iPhone separately tracks current-room reconnect callbacks and displays Reconnecting until transport recovery; a connected SDK state alone never authorizes an ordinary stimulus. Preserve both callback and native UI observations. If testing input during a known transport fault, declare it an intentional fault scenario rather than ordinary listening input. Room recreation changes the room identifier and job; timelines retain those identities so events from the replacement worker are not treated as uninterrupted operation.

For voice transfer, preserve the native target name and a read-only VM route-state observation before permitting the next target-specific input. Verify the actual target thread, route version, saved file changes and production build, then exercise a spoken return to the dispatcher. A changed header or a spoken handoff acknowledgment alone does not establish that the next instruction reached the intended thread. Keep provider timeout values in VM timing records so a slow-link replay proves the effective runtime options rather than merely the source defaults.

Source updates and a voice-worker restart alone do not prove generated instruction freshness. The direct-transfer loader refreshes managed instruction files before reading its default; explicit custom instruction paths retain priority. Retain evidence of the effective loaded text, and restart the API and voice services after Python source updates so long-running processes do not retain old modules. A partly unclear request should ask about that part while completing clear, independent, reversible work; verify the actual files and build before accepting that behavior.

For a multi-turn capture, assess each relevant response with `assess.py <run> --stimulus-index <index> --terminal-phrase "<actual ending>"`. Its window ends at the next host stimulus, and its separate `timing-assessment-stimulus-<index>.json` prevents a later response or microphone-enable from masking an earlier failure. An observed terminal phrase in a clarification is still not evidence that the requested work completed; retain the independent functional assessment.

An Appium time call can fail without returning a parsable timestamp. Keep that observation in the raw probe file; never guess or backfill its device time. The renderer excludes invalid probes, records their errors in clock-bounds.json, and displays the excluded count on each diagram. Valid nearby probes remain usable; a source with no valid calibration remains explicitly uncalibrated.

TTS stream audio-event gaps of at least one second are logged individually and shown on the VM lane; stream completion retains the maximum gap. These are event-delivery intervals observed by the agent wrapper, including consumer scheduling or backpressure, not measured network packet gaps or physical speaker silence. Corroborate them with decoded phone media and the room waveform before attributing an audible interruption.

The microphone lane labels LIVE, MUTED, IDLE and UNKNOWN in every detail window, including a state carried from an earlier window. TTS stream exhaustion is not playout completion: the delivery ledger advances its estimated queue end for each audio frame and excludes underflow gaps from played audio. Its deferred release and stream-end events appear on the VM lane; the phone's decoded media and actual microphone acknowledgment remain necessary acoustic verification.

Lifecycle messages can arrive through multiple transports. Teardown checks deduplicate packet identifiers and ignore a delayed audio-finished message only when the same delivery already received safe-to-unmute with the exact same creation timestamp. Raw receipt records remain in the timeline; different deliveries, newer work and reconnects still block teardown. Passing that check authorizes ending an already quiet, completed capture and does not establish that an earlier microphone release was correct.

For a congestion/recovery scenario, run `python3 voice-tests/network_recovery.py <run-vm> <owned-network-directory> <new-capture-directory> --after-recorder-s 230` beside the capture process. It waits up to 90 seconds for recorder readiness, rejects a stale capture or a recovery scheduled after the independent guest rollback, and records actual restore start/end and exit status on the host lane. Keep the guest rollback armed as the safety fallback and inspect the owned anchor and pipes afterward. This schedules recovery relative to the actual recorder, not call-start or stimulus-request time.

The iPhone retains a bounded per-call history of accepted lifecycle packet identifiers, so interleaved packet and participant-attribute copies cannot reapply an earlier event. Replacement rooms clear that history. Duplicate receipts remain visible as ignored events in the timing diagram; they do not reset the latest accepted delivery context.

After a fresh prepared clone boots, retain its first doctor observation and wait for all expected ports and services to settle before joining a call. A launchd process can be present before its API listener is ready; an initial 34/35 followed by 35/35 without intervention is a cold-start transition. Diagnose persistent failures from bounded service logs rather than repeatedly restarting a healthy process. Native pairing and Listening remain separate gates.

Read the onboarding skill in the disposable preparation VM and follow its first mark-as-read step before sealing. Personal email, calendar, messaging and other external integrations are outside this installation-excluded fixture. Preserve the generic onboarding acknowledgment marker as a hashed fixture asset so fresh dispatcher prompts do not carry unrelated pending-onboarding guidance. Never mark the developer host as onboarded on behalf of a disposable VM.

After a heading steer, compare the current React component with the task result and latest build log. A stale result can produce a false failure report even when the component changed and rebuilt successfully. Fixture briefings require refreshing result.md on every steer and define heading as the visible main component heading. Preserve the contradiction first; verify current source rather than silently rewriting the old evidence.

Accepted later steers supersede conflicting original briefing content. Retain the owner's latest turn prompts alongside source and build output during verification. If STT changes a folder name, inspect the actual parent directory and recorded task locations before reporting that the folder is absent. A clear recognition variation can be resolved from that evidence; genuinely competing targets require clarification and remain a separate functional finding.

## Unanswered clarification and spoken filenames

An unrelated request does not answer a pending clarification. Record the actual registered text, dispatcher tool prompts and task boundaries before concluding that steering reached the wrong owner. The dispatcher must withhold only the unresolved change, continue independent clear work, and preserve unambiguous words when spelling resolves one word. Use [clarification-continuation.json](../voice-tests/scenarios/clarification-continuation.json) to request a choice, perform an unrelated verification, then explicitly confirm the choice. Compare source and turn creation before and after each input; a spoken acknowledgment alone is insufficient.

Speech does not reliably preserve punctuation in filenames. The Elm briefing specifies the canonical correction result path, and the regular stalled-command stimulus refers to that path instead of dictating its hyphen. Retain older hyphen-to-underscore recognition failures as separate input mismatches; a stopped PID and same-turn completion can establish interruption even when exact-filename requirements fail.
