# Accelerated voice tests

Use this track when installation is already understood and the question is how the dispatcher, Super Agents, phone audio, and mute lifecycle behave during a real call. Each run starts from a fresh clone of a **stopped, prepared Tart fixture**, with the developer installation and dedicated test-account login already complete. This provides repeatable voice coverage without reinstalling the product. It provides **no installation coverage**. A retained, modified run VM is debugging evidence; fix, refresh the prepared fixture, and repeat from another fresh clone before reporting the fix as verified.

The [field-testing skill](../.agents/skills/field-testing/SKILL.md) owns all shared phone, Appium, account, permission, speaker, acoustic-loop, model, and reporting gates. Follow its Appium-first and early iPhone VPN-passcode ordering before preparing the computer. The user enters any physical-device passcode directly; a test must record whether the actual VPN passcode sheet appeared. This page owns only prepared-fixture mechanics, scenario timing, and evidence interpretation.

## Prepare and seal a fixture

1. Clone the maintained clean OS image once. Install the developer workspace using [DEV_RUNBOOK](DEV_RUNBOOK.md), with Cloud environment and transport chosen before setup. Use the real reserved field-test signup, delivered verification email, and paid mock entitlement from the shared skill. Complete browser OAuth against the chosen Cloud environment, approve the guest's VPN background item visibly when requested, and require `openbase-coder doctor` to pass. The desktop Electron dashboard is optional for this CLI/voice fixture.
2. Stage current, signed mobile field-test builds. Record the actual workspace, CLI, Super Agents, SDK, and mobile revisions and any dirty patch digest. Rebuilding a phone app can stop its VPN and return it to pairing; reconnect through its onboarding UI and wait for the private backend to become reachable. Keep normal phone apps untouched. Enable Verbose Audio Playback Diagnostics in iOS Settings for these timing runs; leave Auto-mute and Auto-unmute enabled.
3. Prepare two short, speech-friendly Desktop folders, for example Maple and Cedar, with briefings for React Tetris and chess. Briefings request a build, a file-backed result, and a short completion announcement with the agent's assigned speaking name. Do not request an introduction: it must arrive unsolicited. Choose and record the fixture permission state. For a full field test, reset only guest Desktop-folder TCC so the clone exercises the shared permission gate. For an explicitly accelerated voice-only run, first exercise that gate in the preparation VM and retain the visible grant; this avoids blocking a timed voice scenario on a setup dialog. A retained grant provides no fresh permission-gate coverage. Keep fixture credentials and operational manifests in ignored local storage.
4. Stop the preparation VM. Write a reviewed JSON provenance file with `revisions`, `doctor_passed`, `cloud_environment`, `fixture_account`, and `desktop_permission_state` (`reset_for_permission_gate` or `granted_for_accelerated_voice`). Older manifests with `desktop_permission_reset: true` remain accepted as the reset state. Seal it, then create a fresh run clone:

```bash
python3 voice-tests/baseline.py seal <prepared-vm> <versioned-baseline> \
  --manifest .local/field-tests/voice-baseline.json \
  --provenance .local/field-tests/provenance.json \
  --observed-runtime .local/field-tests/observed-runtime.json
python3 voice-tests/baseline.py clone <versioned-baseline> <run-vm> \
  --manifest .local/field-tests/voice-baseline.json
tart run <run-vm>
```

Keep the master stopped and unchanged. Authenticated clones retain the dedicated fixture network identity, so **never run the master, preparation VM, or two clones simultaneously**. The clone helper checks its recorded siblings; also check the preparation VM in `tart list`. Do not upload or distribute an authenticated image. Refresh a versioned fixture when code, toolchains, configuration, account entitlement, or service credentials change. Do not silently update an existing master or report old source as current coverage.

Before stopping the preparation VM, run `python3 voice-tests/provenance.py <prepared-vm> .local/field-tests/observed-runtime.json`. This reads actual guest and host Git heads, branch names, tracked dirty-patch SHA-256 digests and untracked counts. The seal helper requires this observation to be at most thirty minutes old, checks reviewed guest heads, and rejects tracked patches unless `allowed_tracked_patches` explicitly records their observed digest. Compare observed guest revisions with the reviewed seal manifest; a requested revision or host checkout is not proof of the guest runtime. Record signed mobile build artifacts and Appium installation evidence separately: host mobile source alone does not identify the installed binary. Correct a mistaken historical manifest explicitly and retain the correction; create a new versioned master for current coverage.

Inspect the complete doctor summary after the refreshed services are ready. Doctor can exit zero while reporting startup warnings, such as an API port not yet listening; exit zero alone is insufficient to set `doctor_passed`. Retain that initial observation, repeat the read-only check once startup settles, and require every reported check to pass before shutting down and sealing. Do not inherit the previous fixture's successful doctor boolean when recording a new revision.

## Explore the voice scenarios

Reusable source fixtures live in [voice-tests/fixtures](../voice-tests/fixtures): stage each briefing into a new guest Desktop folder named maple or cedar before sealing, and record both actual hashes. [parallel-steer.json](../voice-tests/scenarios/parallel-steer.json) exercises concurrent starts, unsolicited introductions, separate heading steers and file-backed build verification. [transfer.json](../voice-tests/scenarios/transfer.json) exercises a folder-targeted handoff, an explicitly spelled correction and spoken return. [long-story.json](../voice-tests/scenarios/long-story.json) provides a shorter, clear input for full-response acoustic comparisons on either phone. These are driver schedules, not automatic pass criteria; native gates and actual thread/file/build checks still apply. Prepare their WAVs before a call, retain the exact digests, and use folder targets rather than hard-coded speaking names. Run exploratory ambiguity or intentional-overlap variants as separately named cases.

On Android, grant the physical app's microphone permission through Appium before the first call. Native readiness XML may use Java class names as element tags; match bounded, displayed elements rather than assuming `<node>` tags. Use `permit.py --platform android` for Android and retain rejected gate observations. Speaker-button styling is insufficient if it disagrees with the native route acknowledgement: obtain the actual SDK-selected output device and verify room audio before assessing output playback. Android Appium device time may round to whole seconds even when a millisecond format is requested; record its actual one-second resolution and show that uncertainty in diagrams.

Participant audio levels and lifecycle completion are signaling observations, not proof of audible playback completion. Under constrained networking, decoded media can arrive after both. Keep a separate decoded-buffer timeline, annotate that these callbacks precede physical playback, and compare them with recorded room words and actual microphone SDK acknowledgements. A capture that ends before backend generation and speech finish is incomplete observation, not evidence of early TTS stopping. Terminal words spoken in the host prompt never count as an app completion marker; search after the stimulus interval and verify the response context.

Start with a short recorded dispatcher response. Then ask it to start both agents in the separate Desktop folders during one spoken turn. Observe and handle the actual guest Desktop-access alert through computer control. Capture the dispatcher confirmation, both unsolicited introductions, background progress/completion announcements, and actual file/build results.

Steer each agent separately by its durable thread identity. Try corrections while the agents are still working, fragmented sentences, a brief hesitation followed by an addition near the mute boundary, and an addition after the dispatcher has already submitted a turn. Confirm that each instruction reached the intended agent exactly once and that it changed the resulting work. Exercise transfer to an agent and return to dispatch. Do not judge successful steering from a dispatcher acknowledgment alone.

Repeat with constrained guest bandwidth, latency, and loss before spending the remaining effort on platform parity. Shape only traffic inside the disposable guest, preserve and restore its previous firewall configuration, and record the active rules plus measured throughput/latency. Keep host and physical-phone networking unchanged. Distinguish a constrained computer leg from a constrained phone leg; guest shaping does not simulate poor phone Wi-Fi. Restore shaping after each run, including failed runs. Never label a configured limit as a measured network condition.

`voice-tests/network.py apply <run-vm> <ignored-network-directory>` installs only its owned Apple dummynet sub-anchor and reserved pipe IDs. It preserves TCP port 22 for SSH management and arms an independent guest rollback timer before loading shaping rules. The default timer is ten minutes; choose `--safety-seconds` to cover the scenario, up to thirty minutes. Use `restore` afterward and inspect actual PF state, the owned anchor and pipe list. Do not replace the guest's main ruleset or flush other pipes. `dnctl pipe delete <id>` is required for precise pipe cleanup; its unqualified delete can target the wrong object. HTTP download/upload probes must measure the configured profile before acoustic coverage. ICMP can be filtered even without shaping; compare unshaped probes and use measured HTTP timings when ping is unavailable. A configured packet-loss probability is not a measured end-to-end loss rate. Keep measurement traffic outside acoustic runs so it does not silently saturate the constrained link.

## Capture and regenerate timing evidence

`voice-tests/capture.py` reuses the shared Cartesia/AssemblyAI acoustic probe. A scenario JSON contains `seconds` and ordered `stimuli` entries with `at_s` and `text`; offsets are the earliest requested times after recorder readiness. Ordinary stimuli wait for a request-specific native readiness permit. Delays are recorded rather than silently treating the original schedule as the actual playback time. Use enough capture time for the final response and announcements; `response_tail_s` defaults to ten seconds and reserves a minimum response interval. A scenario schedule is instrumentation, not a replacement for agent-driven observation or Appium phone control.

```json
{"seconds": 40, "stimuli": [{"at_s": 2, "text": "What is seven times six? Say complete answer delivered after the answer."}]}
```

```bash
python3 voice-tests/capture.py .local/field-tests/scenario.json \
  .reports/voice-run/ios-smoke --credentials-file <private-env-file> --vm <run-vm>
uv run --with matplotlib python voice-tests/timeline.py .reports/voice-run/ios-smoke
python3 voice-tests/assess.py .reports/voice-run/ios-smoke --terminal-phrase "complete answer delivered"
python3 -m unittest discover -s voice-tests -p 'test_*.py'
```

Only the Cartesia and AssemblyAI keys are extracted from the optional credentials file; existing environment values take precedence. Never source a broad private env file. Artifacts include the original native room WAV, converted WAV, scheduled stimulus audio, provider word spans, host process events, sample-clock mapping, normalized event JSON/CSV, and PNG/SVG timing plots. Save them with a durable Markdown report under `.reports`; do not force-add ignored reports to a public repository.

Use `--reuse-stimuli <previous-run-directory>` for an exact acoustic regression replay. Ordered stimulus texts must match; the previous WAV files are copied without resynthesis, and durations plus SHA-256 digests are retained in `stimulus-provenance.json`. Numeric ASR formatting or digit-by-digit pronunciation can be ambiguous; corroborate semantics against actual sound and use long prose with a unique terminal phrase for independent early-cutoff coverage.

For each ordinary stimulus, wait for `gates/request-N.json`, obtain a fresh native page source through Appium MCP, and save its XML immediately in the gate directory. The iPhone must visibly show Listening, a connected room, an active call, and enabled Mute and End buttons inside the screen viewport, with no Unmute button. Verify the selected speaker styling by screenshot after every call restart. Run the permit helper within 1.5 seconds of saving the fresh observation:

```bash
python3 voice-tests/permit.py <run>/gates/request-0.json \
  <run>/gates/native.xml --speaker-verified
```

Never refresh an old snapshot's modification time to satisfy the gate. A permit expires after 1.5 seconds and belongs to one request nonce. A rejected or missing permit produces no stimulus; the recorder continues so failed tests retain acoustic and sample-clock evidence. This gate reduces harness mistakes but cannot prevent an announcement racing after observation: classify that race from the native journal and recording. Use `mode: "overlap"` only for an explicitly intentional interruption scenario, and keep it distinct from ordinary steering coverage. Cartesia emits floating-point WAV; use `ffprobe` for stimulus durations rather than Python's PCM-only `wave` reader.

Do not end a call just because the recording deadline passed. A delayed backend result can begin TTS at the end of the capture; preserve the call and start another passive capture if needed. Pull a fresh native journal, obtain a new listening snapshot, and run `python3 voice-tests/finish.py <run> <fresh-snapshot.xml> --platform <ios-or-android>` before teardown. It requires the current call's accepted safe-to-unmute and actual mic-enable acknowledgement, plus fresh native Listening and Mute controls. A failed check means keep the call active. Record actual teardown request/acknowledgement timestamps; a later announcement can still race the observation. An agent ending the call during app speech is a harness error, never an app TTS-cutoff finding.

The assessment helper measures the terminal phrase only after the completed host stimulus, so words spoken in the test question cannot satisfy response completion. It retains clock and ASR uncertainty, reports uncertain boundaries without a pass, and does not infer early TTS truncation from a missing phrase alone. Keep manual acoustic findings and the generated `timing-assessment.json` together; an existing harness failure cannot be overridden by these measurements.

The dedicated iOS field-test variant writes already-redacted diagnostics to Documents/`voice-timing.jsonl`; the normal app does not enable persistence or file sharing. The Android fieldTest variant writes whitelisted voice events to its external-files `voice-timing.jsonl`. Both rotate at 16 MiB, retaining one `.previous` file. Pull both files through Appium MCP after every scenario, before rotation can discard them: iOS uses `@<field-test-bundle-id>:documents/voice-timing.jsonl`, Android uses `/sdcard/Android/data/<field-test-package>/files/voice-timing.jsonl`. Save iOS records as `ios.jsonl` and Android records as `android.jsonl`; normalization accepts direct journal entries and deduplicates overlapping iOS uploads. Check persistence failures and the first/last retained timestamps. The in-memory iOS upload buffer contains only 1,000 entries and can lose the beginning of a single long call; it is a fallback, not adequate evidence for a missing interval.

Plots include an overview, SVG/PNG detail views every twenty seconds, and a `timeline.html` index. Separate lanes show recorded sound, recognized acoustic words, host stimulus processes, VM lifecycle publication, phone receipt, acknowledged microphone application, and native playback-level diagnostics. Missing initial microphone history is hatched UNKNOWN. Native audio-level samples corroborate playback activity; they are not proof of audible word completion.

Collect a bounded `livekit-agent.log` tail as `server.log`. Ask the foreground iPhone to upload retained diagnostics using `openbase-coder user ios upload-logs`, then collect a bounded `ios-app.log` tail as `ios.jsonl`. Wait for the upload to finish; command delivery only confirms receipt. Include the relevant Django log records in `server.log` for `ios_control_round_trip`. Upload before and after scenarios to avoid losing the bounded phone buffer. Existing uploads may overlap; normalization deduplicates identical entries and ignores an incomplete first line from a bounded tail. For Android, provide actual native event records as `android.jsonl` with `unix_ms`, `event`, and metadata; absent Android events must be reported as missing instrumentation, never invented from server events.

Each acknowledged iPhone control command logs its native receipt and the server send/ack interval with the same command ID. The causal inequality bounds **phone clock minus VM clock** without assuming symmetric latency. Measure VM clock minus host clock with timestamped SSH round trips; store the resulting midpoint and half-width as `{"server":{"offset_ms":...,"uncertainty_ms":...}}` in `clock-calibration.json`. The plotter combines those intervals, retains native timestamps, rejects contradictory phone bounds, and marks uncalibrated clocks explicitly. Repeat calibration around a run; clock jumps or conflicting bounds invalidate a merged timing claim.

With `--vm`, capture brackets the recording with warmed SSH probes so SSH connection setup is excluded from each causal interval. The collector retains separate probe batches and uses their offset envelope; it does not falsely intersect drifting offsets from different times. Probe bounds describe the clock at those observations and assume no larger excursion between bracketing probes. The plotter excludes VM and server-mediated phone probes more than 120 seconds outside the recording. Retrospective calibration far from a run cannot establish submillisecond accuracy for that run. A within-batch conflict invalidates calibration. Keep before/after native phone-time samples and raw probe batches in the report.

Alternatively, bracket Appium MCP's device-time request with host wall timestamps, request millisecond ISO formatting (`YYYY-MM-DDTHH:mm:ss.SSSZ`), and save samples in `device-clock-samples.json`. Each sample contains `source` (`ios` or `android`), `host_before_unix_ms`, `host_after_unix_ms`, `device_unix_ms`, and `timestamp_resolution_ms`. The native clock lies between request and response, yielding an interval rather than a symmetric-delay estimate. The plotter intersects samples within a contiguous batch and retains the envelope of separate batches; probes more than 120 seconds outside the recording are excluded. Preserve raw samples and repeat around long runs. Android can round this result to whole seconds despite the requested format: use `timestamp_resolution_ms: 1000`, and sample repeatedly across second boundaries to tighten the causal interval without claiming nonexistent millisecond precision.

Android's field-test clipboard export adds a native `native timing export requested` record with a fresh `probe_id`. Bracket the tap and clipboard retrieval, require a new ID, and record the probe's native `unix_ms` with one-millisecond timestamp resolution. Export runs asynchronously after the tap: the gesture acknowledgement alone is not a valid upper bound. Clipboard retrieval can take over a second; show that uncertainty and combine only with independent, consistent clock observations. Appium UiAutomator2 idle and selector waits can be inspected and adjusted through the registered `appium_driver_settings` MCP tool; retain the settings used in the report.

The first Core Audio tap maps the first recorded sample's host time to wall time and reports frame counts and sample discontinuities. `afplay` process start/end are scheduling markers, **not audible onset/end**. Use the recorded waveform and recognized words to judge actual sound. AssemblyAI word offsets are milliseconds from the WAV start but are estimates; its [published guidance](https://support.assemblyai.com/articles/6819078983-does-your-api-return-timestamps-for-individual-words) describes roughly 400 ms accuracy. Retain the waveform and review finer mute boundaries against it or a more precise alignment method. Millisecond log formatting does not establish millisecond clock accuracy or prove that the speaker played those words.

Preinstall analysis dependencies before joining the acoustic call. After a completed capture, run `uv run --with scipy python voice-tests/acoustic_alignment.py <capture>` to correlate each retained stimulus waveform with the room microphone recording. The result retains both file hashes, correlation scores and estimated fixture signal boundaries; matches below 0.2 are untrusted and omitted from plots. Then regenerate `timeline.py` to show the waveform estimate beside the process interval. Its 10 ms display allowance is an analysis assumption, not a calibrated physical uncertainty bound, and these fixture amplitude boundaries are not exact semantic word boundaries. Run the full optional alignment checks with `uv run --with scipy python -m unittest discover -s voice-tests -p 'test_*.py'`.

Do not promote a negative primary ASR/microphone gap directly to a confirmed app defect. A later click or transient can extend the final word beyond its actual spoken end, including beyond the approximate ±400 ms allowance. The assessor flags a candidate requiring waveform review. Retain the unchanged primary alignment, obtain a bounded independent alignment when needed, and record the corroborated conclusion separately. In the overnight regression, independent alignment confirmed the original early unmute but exposed several later primary-only false candidates.

For each scenario, report user speech end → turn acceptance → mic mute, server audio start/finish → device receipt → audible first/last word, mic unmute relative to audible end, introduction ordering, steer acceptance/target/result, duplicate instructions, gaps, and missing/clipped words. Device-side microphone application and playback-level events corroborate the room recording. If any source is missing, coarse, or uncalibrated, state the resulting limit instead of passing the timing requirement.

Retain normalized backend tool observations in a capture's optional `backend-tools.jsonl` using `source: "server"`, the actual VM `unix_ms`, an event such as `observed super_agents_start_turn`, and metadata with its target thread and timing basis. The renderer applies the VM clock correction and places these beside request/lifecycle events. An adapter's timestamped tool invocation is not a remote acceptance acknowledgement; label that distinction and corroborate actual turn creation/status separately.

## Known setup roadblocks

- A cached `OpenbaseFieldTest.app` may be unsigned. Rebuild for the physical-device destination with `-allowProvisioningUpdates`, then install through Appium. A cached APK can contain older behavior even when its real netmesh library is present; rebuild before claiming current-source coverage.
- Regenerate Tuist after `ios/Project.swift` changes. `OpenbaseFieldTest` is a physical field-test build scheme without a test action; use the `Openbase` scheme and a dedicated simulator for mocked unit tests. The UIKit auth package is iOS-only; a plain host `swift test` is not its supported test path. Test through an iOS Xcode destination.
- SwiftUI can report `visible=true` for an off-screen control, and `scroll_to_element` can stop before the control's center enters the viewport. Verify its bounds and screenshot. A row-wide Settings switch element can cover the text as well as the actual switch; tapping its center may do nothing. Tap the observed switch control and assert its new value. Recheck Verbose Audio Playback Diagnostics and the speaker route after installing a new build.
- Gradle needs a JDK even if an old APK exists. Set `JAVA_HOME` to an installed JDK 17 before rebuilding; do not infer a runtime from the presence of Gradle caches.
- Appium MCP's Android file-pull wrapper may send `path` where UiAutomator2 requires `remotePath`. If the registered tool reports that exact mismatch, use the field-test Settings action **Copy Voice Timing Diagnostics**, then retrieve the clipboard through Appium MCP. It flushes pending journal writes and exports up to 400,000 bytes of complete recent records. Check that the export covers the whole scenario; the fallback is bounded and cannot prove missing older intervals. Do not use an ad-hoc adb/WebDriver workaround.
- On some guest builds, `dnctl list` omits later pipes once a preceding pipe has active flow queues. Record both configurations before loading shaping rules and measure both traffic directions; a post-traffic textual omission alone does not establish that a pipe vanished. Treat an unmeasured direction as missing coverage.
- A local cached Electron bundle without a bundled runtime is not a signed-DMG installer sample. For developer voice tests use `./scripts/setup`; omit Electron or use the developer dashboard launcher from the developer runbook. Do not report the cache's missing CLI as an installation regression.
- Browser OAuth can open outside the existing Safari automation session. Adopt the real guest browser through the Tart Safari harness after confirming the Cloud origin, then use semantic controls. Disposable-guest helper approvals and credentials are agent-controlled; do not ask the user to operate the VM.
- Restart the guest voice worker with `openbase-coder services stop livekit-agent`, then `openbase-coder services start livekit-agent`. `services restart` is not a supported subcommand. Reconnect the physical call after replacing worker code; an existing room job continues to run its already-loaded module.
- Android's active VoIP call uses the voice-call stream; media volume and the app's volume slider do not establish its actual loudness. Check native `voice_call_volume` against `voice_call_max_volume` during a connected call, use physical-device volume keys through Appium MCP when needed, and verify the response acoustically. Speaker styling and decoded PCM alone do not prove audible room output. Record the SDK-selected route and native communication device rather than relying on deprecated speakerphone flags.
- Run Tuist generation before starting Xcode builds. Regenerating the project while a signed build is running can change entitlements and invalidate that build. Record the build result and actual Appium installation separately from the source commit.
- Read-only guest log and provenance observations retry at most three SSH transport failures. Do not retry a mutation whose acknowledgement was lost: inspect actual state first. Network restoration timers carry an ownership lease, so an obsolete timer cannot flush a newer profile's pipes or anchor.

Run all throughput probes to completion before acoustic recording. An overlapping upload competes with streaming STT inside the shaped guest; treat it as an explicit competing-traffic scenario rather than ordinary steady-state network coverage. Record network restoration in host events when it occurs during a capture. A VAD-only hold without any transcript must expire, while a hold owned by actual backend work or pending speech remains protected.

An AssemblyAI no-messages or no-audio warning can occur normally during silence or automatic muting. The collector labels it `stt_provider_warning`; the warning alone does not establish STT starvation. Establish a stall from an actual recorded input, transport state, missing transcripts, and the resulting recovery behavior. Historical `stt_provider_stall` labels require the same corroboration.

Inspect the visible Tart window promptly when a dispatched turn stops progressing. Precreating Desktop folders over SSH does not prove that the coding backend has Desktop permission: a different runtime can still trigger a modal. Record the actual Allow action as `vm_desktop_permission_allowed`, preserve the delayed run as partial evidence, and repeat from a fixture with the declared permission state. Do not count omitted, gated stimuli as successful steering. Core Audio capture metadata records the actual input device ID, name, and UID; record output routing separately and verify sound in the room recording.

Run `python3 voice-tests/measure_network.py <run-vm> <ignored-network-directory>` after applying a profile and before acoustic recording. It performs bounded, sequential Cloudflare HTTP download/upload probes with a generated zero-filled upload body and retains rates, durations, byte counts, and failure status. A failed direction remains unmeasured. Wait for the command to finish before starting the scenario; preserve its host start/end times beside the capture to prove that measurement traffic did not overlap input.

Specify the exact result path in each briefing, for example `~/Desktop/Maple/result.md`, separately from the React app directory. Agents can legitimately create a nested app folder; a missing result at a guessed parent location does not imply an active turn. Check actual thread status, locate the requested output, and run the build. Retain both canonical skill revision and guest runtime revisions when refreshing a fixture: dispatcher procedure changes are part of the tested source.

If a terminal word is ambiguous in the primary transcript, run `python3 voice-tests/secondary_transcript.py <run> --start-s <bounded-interval-start> --seconds 10 --credentials-file <private-env-file>` for an independent Deepgram Nova reading. It extracts only the Deepgram key, retains the original room WAV digest and clip offset, and preserves the primary transcript. Two providers agreeing still does not establish exact acoustic timing or the intended words: compare the actual backend text and waveform, and retain uncertainty instead of changing a failed marker into a pass.

After booting a fresh clone, service PIDs can appear before the API and LiveKit sockets are listening. Require a fresh `openbase-coder doctor` with all checks passing before the call; preserve earlier startup observations and recheck readiness rather than treating a PID as socket health or a transient boot warning as a product failure. Timing diagrams include registered VM STT excerpts and a full receipt-time table so input recognition errors can be distinguished from output clipping.

`finish.py` requires `--vm <run-vm>` and checks the dedicated fixture backend store for running, waiting, queued, or starting turns, including background agents. A premature native unmute does not authorize teardown while actual backend work remains pending. Capture the fresh phone snapshot immediately before running the helper; its freshness is checked after the backend observation. Do not end a call just because a recording deadline elapsed, or because one dispatcher delivery finished while agent announcements are still owed.

AVAudioEngine can report an internal `CADefaultDeviceAggregate` as its logical input. Capture metadata also records the system default input and output devices at recorder startup; retain both, and do not describe the internal aggregate name as proof of a particular physical microphone. These device observations are configuration evidence, while audible phone responses in the room recording establish the acoustic loop.

An app-control receipt timeout is an unknown outcome, not proof that the foreground app is closed or that the action failed. The phone may already have executed the command; inspect actual state before retrying. The diagnostics collector continues waiting for an observed log append after an unconfirmed receipt and records that distinction in `collection-attempts.jsonl`. Successful append observations clear the current upload error while preserving the prior error in history. Native Appium journals remain the authoritative fallback.

For extreme upload profiles, use `measure_network.py --upload-bytes 100000` (the default is one million bytes) so a bounded probe can finish within its 45-second limit. Retain the requested byte count and measured duration; small transfers include proportionally more connection overhead. A bounded secondary transcript is drawn in green alongside the unchanged primary ASR words in blue. An ASR word extending across a mute feedback sound is timing uncertainty until independently checked against the waveform and native mic application.

A stimulus may contain `segments: [{"text": "First instruction.", "gap_after_s": 1.8}, {"text": "Actually, use this correction."}]`; its top-level `text` must exactly equal those fragment texts joined with spaces. The capture harness synthesizes each fragment, converts to mono PCM, inserts sample-exact silence, and retains source digests and offsets. These offsets describe the fixture WAV, not exact speaker onset; use the recorded room waveform to verify acoustic pauses. Reused fixtures retain the same original WAV digest.

After replacing a signed iPhone build, wait for onboarding to settle, reconnect Openbase VPN through its visible Connect control if needed, and verify the native call screen before starting capture. An element query immediately after activation can run before that screen appears. Keep the phone foreground during VM restart/clone socket tests; background/foreground would repair the connection and invalidate a claim that periodic heartbeats recovered it. Socket diagnostics retain native heartbeat sent/completed/timeout timestamps without logging credentials.

Use `capture.py --prepare-only` to synthesize a scenario into an ignored fixture directory before joining a call. It creates the scenario, WAVs and provenance without playing or recording. Pass that directory with `--reuse-stimuli` for real captures; reuse checks retained WAV digests and keeps fragment/pause metadata. This separates provider preparation from the acoustic observation window.

Deterministic Super Agent names are case-sensitive: `Orange` and `orange` map to different speaking names. Voice STT may lower-case a requested durable thread name. Use lower-case durable names in voice fixtures, verify the actual stored `name` and `agent_name` before naming targets in later stimuli, and compute completion commands from that exact stored name. Prefer folder/task targets in reusable steering audio; a conflicting person name and folder is an ambiguity scenario, not ordinary steering coverage.

Hash staged briefings with `provenance.py --asset Desktop/orange/briefing.md --asset Desktop/willow/briefing.md`; retain their portable paths and SHA-256 values as `test_assets` in the reviewed sealing provenance. After booting the fresh clone, run `provenance.py --fixture-manifest <manifest>` before any call. Missing or changed assets write evidence and fail validation. Source heads alone do not prove that staged task files survived cloning. Before sealing, flush guest writes and shut the guest OS down normally; do not assume the VM-process termination timeout proves macOS completed its own shutdown. Tart's [stop implementation](https://github.com/cirruslabs/tart/blob/main/Sources/tart/Commands/Stop.swift) sends SIGINT, while its [run implementation](https://github.com/cirruslabs/tart/blob/main/Sources/tart/Commands/Run.swift) handles guest stop requests separately. The post-clone asset hashes remain the actual evidence.

Prefer spoken “read the briefing file in each folder” to dictating an extension. “Dot markdown” can resolve to `.markdown`, whereas a staged file may be `.md`. Keep exact file names in the briefing and verify the agent used that actual file. A missing staged briefing or filename ambiguity is a harness finding even if the agent creates an otherwise valid app.
